# Epic 05.5 — Test Infrastructure: Results

## What Was Built

A standalone seed script (`scripts/seed-test-data.ts`) that creates two test workspaces with seeded data for development, e2e testing, and demos. Run with `npx tsx scripts/seed-test-data.ts`.

- **Mock workspace** (`seed-mock@expliq.dev`): 19 automations with crafted mock n8n workflow JSON and intentionally diverse governance fields producing all 3 risk levels and all 4 impact levels
- **Real workspace** (`seed-real@expliq.dev`): ~10 automations synced from a live n8n instance, LLM-processed

## Script Structure

1. Imports (`dotenv/config`, prisma singleton, encrypt, createN8nClient, processAutomation, risk-engine, bcrypt)
2. Constants + helpers (`daysAgo`, `cleanupWorkspace`)
3. 19 mock n8n workflow JSON definitions (2-6 realistic nodes each, using real n8n node types)
4. Governance field matrix (per-automation owner, status, timestamps, review dates)
5. `seedMockWorkspace()` — insert automations, run LLM, safety net for impact diversity, insert unprocessed
6. `seedRealWorkspace()` — n8n sync + LLM (skipped if creds missing)
7. `printSummary()` — impact/risk/signal distributions using risk-engine functions
8. `main()` with env checks and graceful degradation

## Decisions and Deviations from Spec

1. **Governance field restoration after LLM** — `processAutomation()` sets `documentationLastUpdated = new Date()` on every processed automation. This overwrites the governance matrix values that control the `documentationOutdated` signal. Added a Step 6b that re-applies governance fields after LLM processing completes. Without this, automations designed for `documentationOutdated = true` would lose that signal.

2. **Mock-10 timestamp correction** — Original plan had `automationLastUpdated: daysAgo(60)` and `documentationLastUpdated: daysAgo(45)`. Since `daysAgo(45)` is more recent than `daysAgo(60)`, this made `docOutdated = false` (doc was newer than automation), reducing signals to 2 (medium risk) instead of the intended 3 (high risk). Swapped to `automationLastUpdated: daysAgo(45)`, `documentationLastUpdated: daysAgo(60)` to produce the correct 3 signals.

3. **Sequential LLM processing** — LLM calls remain sequential (not parallelized). Each call takes ~10-12 seconds; full run with 25 automations takes ~3-4 minutes. Parallelization could be added but wasn't strictly needed for a seed script.

4. **Uses prisma singleton** (not standalone PrismaClient) — Since `processAutomation` imports the singleton, the seed script uses the same singleton for consistency. This differs from the `verify-risk-engine.ts` pattern which creates its own client.

5. **Explicit Account/Session cleanup** — Added `account.deleteMany` and `session.deleteMany` to the cleanup transaction even though they cascade from User deletion. Belt-and-suspenders approach for reliability.

## Risks for Future Epics

1. **`documentationLastUpdated` overwrite** — `processAutomation()` always sets `documentationLastUpdated = new Date()` when it processes an automation. Any future epic that re-runs LLM processing on seed data will overwrite the carefully designed governance timestamps. Re-running the seed script restores them.

2. **LLM impact classification uniformity** — As noted in epic 04 results, the LLM tends to classify most automations as "high". The safety net and pre-set `impactOverride` values guarantee diversity, but the `impactProposal` values themselves may cluster. This is visible in the Automation Detail view (epic 07) where both `impactProposal` and `impactOverride` are shown.

3. **Seed data depends on external APIs** — Full seed requires both `OPENROUTER_API_KEY` and n8n credentials. Without `OPENROUTER_API_KEY`, mock automations have null LLM fields (still useful for governance testing but not for LLM field display testing). Without n8n creds, real workspace is skipped entirely.

4. **Existing e2e test workspaces** — The 2 workspaces from epic 02/04 Playwright runs still exist in the DB (email: `e2e-test@expliq.dev`). The seed script does not touch them. They have different data profiles (all high impact, all inactive, no owners).
