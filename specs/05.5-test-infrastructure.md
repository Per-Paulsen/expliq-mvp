# 05.5 — Test Infrastructure

> Upstream: [PRD](../expliq_prd.md) | Previous: [05 — Risk Engine](05-risk-engine.md)

## Scope

Set up a seed script that creates two test workspaces with seeded data for development, e2e testing, and demos. The script produces a **mock workspace** with crafted diverse data (for UI filter/badge/ranking testing and LLM classification diversity validation) and a **real workspace** synced from a live n8n instance (for end-to-end pipeline validation).

### Dependencies

This epic depends on:
- Epic 02 (Authentication) for the User/Workspace models and password hashing with bcrypt
- Epic 03 (n8n Connector) for ConnectorConfig, the n8n client (`createN8nClient`), and the encryption module (`encrypt`)
- Epic 04 (LLM Pipeline) for `processAutomation(automationId, workspaceId)` in `llm-pipeline.ts`
- Epic 05 (Risk Engine) for governance signal computation — seed data is designed to produce all three risk levels

### Script

A standalone script at `scripts/seed-test-data.ts`, invoked via `npx tsx scripts/seed-test-data.ts`. Not a Prisma seed — avoids `prisma migrate reset` which would wipe the shared Supabase database.

### Two Workspaces

| | Mock Workspace | Real Workspace |
|---|---|---|
| **User** | `seed-mock@expliq.dev` | `seed-real@expliq.dev` |
| **Password** | `SeedTest123!` | `SeedTest123!` |
| **Automations** | At least 15 crafted mock workflows + 2 removed | ~10 from real n8n sync |
| **LLM fields** | Generated by LLM from mock workflows | Generated by LLM from real workflows |

### Mock Workspace — Data Design

**At least 15 mock automations** with crafted `rawWorkflowJson` designed to elicit diverse LLM impact classifications. Each mock workflow should be a plausible n8n workflow JSON with recognizable node types, system integrations, and varying business criticality:

- Simple internal notifications (e.g., "new blog post → Slack") → expecting **low** impact
- Data exports/backups (e.g., "scheduled CRM export to Google Sheets") → expecting **low** or **medium**
- Lead routing and CRM updates (e.g., "inbound lead → qualify → assign in Salesforce") → expecting **high**
- Payment/revenue workflows (e.g., "Stripe payment → HubSpot deal update → Slack alert") → expecting **critical**
- Multi-system employee onboarding flows → expecting **high**
- Simple scheduled report emails → expecting **low**

The mock workflows don't need to be full production-size — they need to be realistic enough that the LLM understands the automation's purpose and can classify its business impact.

**Governance fields** are hardcoded on each mock automation (the LLM does not set these) to produce intentional diversity in governance signals and risk levels:
- **Owners**: 3-4 named owners (e.g., "Alice Chen", "Bob Martinez", "Carol Davis") plus several with `null` owner
- **Statuses**: mostly `active`, a few `inactive`, at least one with `statusOverride = deprecated`
- **Review dates**: mix of recent reviews (within cadence), overdue reviews, and never-reviewed (`lastReviewDate = null`)
- **Timestamps**: varied `automationLastUpdated` and `documentationLastUpdated` to produce both stale and outdated-documentation signals
- **Overrides**: a few automations with `impactOverride` set (to test the "LLM proposal vs user override" display), most with `null`

**LLM-driven fields** (`systemsTouched`, `triggerType`, `name`, `description`, `impactProposal`, etc.) are generated by the LLM from the mock workflow JSON. System diversity and trigger type variety are therefore driven by the mock workflow design, not hardcoded. The mock workflows must be crafted to touch diverse systems (Slack, Salesforce, HubSpot, Gmail, Stripe, Google Sheets, Jira, etc.) with several touching 3+ systems.

**Safety net**: After the LLM processes the mock automations, if impact classifications are still uniform (e.g., all "high"), apply `impactOverride` on a subset to guarantee all four impact levels are represented for UI testing.

**2 removed automations** (`status = 'removed'`) to verify exclusion from all views (acceptance criteria in epics 06 and 08).

**1-2 unprocessed automations** with null LLM fields (name, description, etc. all null) to test the "Pending generation" placeholder state in epic 07. These should be excluded from LLM processing (inserted after the pipeline runs, or skipped by the pipeline).

Each automation in the seed data should have an inline comment noting the expected governance signals and risk level.

### Real Workspace — Pipeline

1. Create workspace, user, and ConnectorConfig using real n8n credentials from `.env` (`N8N_INSTANCE_URL`, `N8N_API_KEY`)
2. Sync workflows from n8n using `createN8nClient` from `src/lib/n8n-client.ts` and replicate the upsert logic from the `syncWorkflows` server action (the server action itself cannot be called from a script because it depends on `getRequiredSession()`)
3. Run the LLM pipeline using `processAutomation(automationId, workspaceId)` from `src/lib/llm-pipeline.ts` for each synced automation (this function takes explicit params and has no session dependency)

### Idempotency

Delete-and-recreate strategy. On each run, the script:
1. Looks up users by email (`seed-mock@expliq.dev`, `seed-real@expliq.dev`)
2. If found, deletes in dependency order within a transaction: Automations → ConnectorConfigs → User → Workspace (no cascading deletes in the Prisma schema, so explicit ordered deletion is required)
3. Creates everything fresh

This ensures a clean, predictable state on every run. Only seed workspaces are affected — other workspaces in the database are untouched.

### Graceful Degradation

The script reads credentials from the existing `.env` file:
- **Mock workspace** requires `OPENROUTER_API_KEY` for LLM processing. If missing, automations are inserted with null LLM fields (still useful for governance signal testing). Prints a warning.
- **Real workspace** requires `N8N_INSTANCE_URL`, `N8N_API_KEY`, and `OPENROUTER_API_KEY`. If n8n credentials are missing, the real workspace is skipped entirely with a warning. If only `OPENROUTER_API_KEY` is missing, sync runs but LLM processing is skipped.

### Console Output

The script prints a summary on completion:
- Credentials for both users (email + password)
- Number of automations created per workspace
- LLM processing results (processed count, or "skipped — no API key")
- Real workspace sync results (if applicable)

## Acceptance criteria

- [ ] `scripts/seed-test-data.ts` exists and runs successfully via `npx tsx scripts/seed-test-data.ts`
- [ ] Mock workspace is created with user `seed-mock@expliq.dev` (password `SeedTest123!`) and a workspace
- [ ] Mock workspace contains at least 15 non-removed automations with crafted mock n8n workflow JSON spanning diverse business types
- [ ] Mock workspace contains 2 automations with `status = 'removed'`
- [ ] Mock workspace contains 1-2 automations with null LLM fields (unprocessed state)
- [ ] Mock workspace automations have diverse governance fields: multiple named owners + null owners, mixed statuses (active/inactive/deprecated via statusOverride), varied review dates producing overdue and on-time signals, varied timestamps producing stale and outdated-documentation signals
- [ ] LLM pipeline runs on mock automations (when `OPENROUTER_API_KEY` is set), generating name, description, impact classification, and other LLM fields from the crafted workflow JSON
- [ ] After LLM processing, all four impact levels (critical, high, medium, low) are represented — either from LLM classification or via `impactOverride` safety net
- [ ] All three risk levels (high, medium, low) are represented across mock automations (driven by governance signal combinations per epic 05 rules)
- [ ] Mock workspace has a ConnectorConfig with a dummy `instanceUrl` and `lastSyncAt` set to a recent relative timestamp
- [ ] Real workspace is created with user `seed-real@expliq.dev` (password `SeedTest123!`), ConnectorConfig with real n8n credentials from `.env`, synced workflows, and LLM-processed automations
- [ ] Real workspace creation is skipped gracefully (with warning) if n8n env vars are missing
- [ ] LLM processing is skipped gracefully (with warning) on either workspace if `OPENROUTER_API_KEY` is missing
- [ ] Script is idempotent: running it twice produces no duplicate records and no errors — the previous seed data is cleanly replaced (LLM-generated content may differ between runs)
- [ ] Script only affects seed workspaces — existing workspaces are untouched
- [ ] Script prints a summary with login credentials, automation counts, and processing results

## Out of scope

- Prisma seed integration (`prisma db seed`) — this is a standalone script
- Shared Vitest fixtures or mock factories — unit tests continue to define inline mocks
- Playwright e2e test files — this epic only produces the seed data; e2e test authoring happens in later epics
- Production seed data or data migration tooling
- Cleaning up existing e2e test workspaces from epic 02/04 Playwright runs

## Domain terms

| Term | Definition |
|------|-----------|
| **Mock workspace** | A seed workspace with crafted diverse data designed to exercise all UI states, filters, and governance signal combinations |
| **Real workspace** | A seed workspace populated by syncing real workflows from a live n8n instance and processing them through the LLM pipeline |
| **Seed script** | A standalone TypeScript script that creates test data in the database for development and e2e testing |
| **Safety net** | Post-LLM step that applies `impactOverride` on a subset of mock automations if the LLM didn't produce sufficient impact level diversity |
| **Graceful degradation** | The script's behavior when env vars are missing — it skips the dependent step with a warning rather than failing |
